LAB 01 · Start: projekt, aplikacja i opis pomysłu

Zajęcia nie są oceniane. Na koniec macie działający projekt na GitHubie, uruchomioną aplikację i porządnie opisany pomysł na własny projekt. Od LAB 02 budujecie na tym fundamencie.

Pracujemy na zajęciach, nie w domu. Wszystko z tej instrukcji robicie w trakcie zajęć.

Od tego zaczynamy LAB 02. Na początku kolejnych zajęć każdy zespół uruchamia aplikację w IntelliJ i pokazuje stronę http://localhost:8080 z wypełnioną wizytówką projektu: nazwa projektu, jedno zdanie o problemie, tabela (Autorzy, Dla kogo, Najważniejsze funkcje) i zmiany wprowadzone na LAB 01. Na stronie nie może zostać żaden znacznik [uzupełnij]. Wizytówkę wypełniacie w kroku C3, a wysyłacie na GitHuba w kroku C4.

Materiały: strona główna dokumentacji (czym jest backend, architektura warstwowa, plan 7 zajęć, wymagania, zasady zaliczenia). Aktualna dokumentacja jest dostępna online: wkoszela.github.io/WdTB-2026-Backend--projectname--. Te same strony są w katalogu docs/ repozytorium: po sklonowaniu otwórzcie docs/index.html w przeglądarce.

Plan zajęć

  1. A · Powitanie i omówienie przedmiotu

A · Powitanie i omówienie przedmiotu

Poznajemy się. Prowadzący przedstawia przedmiot i sposób pracy:

  • 7 laboratoriów: LAB 01 nie jest oceniany, LAB 07 służy do odrabiania zaległości,
  • pracujecie w zespołach 3-osobowych nad własnym projektem, wszystko na zajęciach,
  • wymagania każdego laboratorium sprawdzają automatyczne reguły na GitHubie,
  • zasady zaliczenia i obecności: Zasady.

Następnie przechodzimy razem przez sekcje 1–2 strony głównej dokumentacji:

  • Backend to serwer, z którym rozmawia aplikacja webowa i mobilna. Przyjmuje żądanie HTTP, sprawdza reguły, czyta i zapisuje dane w bazie, odsyła JSON.
  • Baza danych przechowuje dane w tabelach powiązanych kluczami. U nas: H2, wbudowana w aplikację.
  • Architektura warstwowa: Controller → Service → Repository → baza. Każdą warstwę zbudujecie na innych zajęciach.

Plan wszystkich zajęć: Roadmapa.

B · Zespół i repozytorium

B1. Arkusz zespołów

Zespół to 3 osoby. Utwórzcie zespoły i wpiszcie je do arkusza zespołów (plik Excel): jedna osoba otwiera zakładkę swojej grupy, wybiera wolny numer zespołu i wpisuje cały zespół (imię i nazwisko, numer indeksu, e-mail uczelniany). Nazwę projektu, link i krótki opis uzupełnicie w części C.

B2. Fork szablonu

Jedna osoba z zespołu hostuje repozytorium. Pozostałe osoby patrzą i dołączają w kroku 3.

  1. Fork. Otwórzcie https://github.com/wkoszela/WdTB-2026-Backend--projectname-- i kliknijcie Fork → Owner: Wasze konto → Create fork. Nazwę forka zmienicie w części C, gdy będziecie mieli nazwę projektu.
  2. Włączenie sprawdzania. Zakładka Actions → I understand my workflows, go ahead and enable them. W forkach GitHub Actions jest domyślnie wyłączony; bez tego reguły nie będą się uruchamiać.
  3. Zespół. Settings → Collaborators → Add people: dodajcie pozostałe osoby z zespołu, żeby mogły wysyłać zmiany. Zaproszone osoby akceptują zaproszenie (e-mail albo https://github.com/notifications). Prowadzącego nie dodajecie: repozytorium jest publiczne, wystarczy link w arkuszu.
  4. Klon. Osoba hostująca pobiera repozytorium w IntelliJ IDEA przez integrację z GitHubem:
    1. File → New → Project from Version Control (na ekranie powitalnym: Clone Repository).
    2. Po lewej stronie okna wybierzcie GitHub → Log In via GitHub…. Otworzy się przeglądarka: zalogujcie się na GitHubie i kliknijcie Authorize. Logowanie wykonuje się jednorazowo; później IntelliJ pamięta konto.
    3. Na liście repozytoriów Waszego konta wybierzcie fork WdTB-2026-Backend--projectname--, sprawdźcie katalog w polu Directory i kliknijcie Clone → Trust Project.
    IntelliJ rozpozna projekt Maven i pobierze zależności. Zamiast logowania można też wybrać Repository URL i wkleić URL forka. Brak JDK 21 lub nowszego: File → Project Structure → SDK → Download JDK. Pozostałe osoby klonują najpóźniej na LAB 02 w ten sam sposób (fork widzą na liście po zaakceptowaniu zaproszenia do zespołu).

Nowe materiały. Na początku kolejnych zajęć kliknijcie na stronie repozytorium Sync fork → Update branch, żeby pobrać nowe instrukcje z docs/.

C · Praca zespołu

Zespół siada razem przy komputerze osoby hostującej. Poznajecie aplikację, opracowujecie pomysł i od razu wpisujecie go do projektu. Na LAB 01 wystarczy, że zmiany zacommituje jedna osoba z zespołu.

C1. Uruchomienie aplikacji

  1. W IntelliJ otwórzcie klasę ProjektApplication i kliknijcie zieloną strzałkę obok metody main → Run 'ProjektApplication'. W oknie Run zobaczycie create table user_account wygenerowane przez Hibernate i na końcu Started ProjektApplication in … seconds.
  2. Otwórzcie http://localhost:8080: strona startowa potwierdza, że backend działa. To ją zamienicie w wizytówkę projektu.
  3. Otwórzcie http://localhost:8080/h2-console (JDBC URL jdbc:h2:file:./data/wdtb, użytkownik sa, hasło puste) i wykonajcie SELECT * FROM user_account;.

Najważniejsze pliki projektu:

Plik / katalog Co zawiera
pom.xml zależności (Spring Boot, JPA, H2) i wersja projektu
src/main/java/pl/wsb/projekt/ProjektApplication.java klasa startowa z @SpringBootApplication
src/main/java/…/account/domain/UserAccount.java jedyna gotowa encja: konto użytkownika (tabela user_account)
src/main/resources/application.properties konfiguracja: adres bazy, konsola H2, logi SQL
src/main/resources/data.sql dane startowe wczytywane przy każdym uruchomieniu

src/test/java/pl/wsb/rules reguły projektu, czyli automatyczne testy sprawdzające wymagania laboratoriów

C2. Pomysł na projekt

Opracujcie koncepcję projektu według strony Koncepcja projektu (wstęp, przykład i warunki).

C3. Wymagane pliki

Wpiszcie pomysł do projektu. Po każdej zmianie zrestartujcie aplikację i sprawdźcie efekt.

  1. Nazwa projektu (R1.01): jedno słowo, małe litery, bez polskich znaków (np. kawiarnia). Fork: Settings → General → Repository name → WdTB-2026-Backend-<nazwaprojektu> → Rename. W kodzie: pakiet pl.wsb.systemobslugiautomyjni → pl.wsb.<nazwaprojektu> i klasa ProjektApplication → <NazwaProjektu>Application (IntelliJ: Refactor → Rename), w pom.xml <artifactId>wdtb-2026-backend-<nazwaprojektu></artifactId>.
  2. Wersja (R1.05): w pom.xml <version>1.0.0-<nrindeksu1>-<nrindeksu2>-<nrindeksu3></version>.
  3. Konta zespołu (R1.03): w src/main/resources/data.sql konta wszystkich osób z zespołu (wzór w komentarzu na końcu pliku). Po restarcie sprawdźcie w konsoli H2, że jesteście w tabeli user_account.
  4. Wizytówka (R1.04): w src/main/resources/static/index.html zastąpcie wszystkie [uzupełnij]: nazwa, jedno zdanie o problemie, autorzy, persona, 3 najważniejsze funkcje i zmiany wprowadzone na LAB 01.
  5. Arkusz zespołów: przy swoim zespole nazwa projektu, link do repozytorium i krótki opis (1–2 zdania). Osoba hostująca zaznacza „tak” w kolumnie Host.

  • pakiet pl.wsb.systemobslugiautomyjni → pl.wsb.<nazwaprojektu> (IntelliJ: Refactor → Rename na pakiecie),
  • ProjektApplication → <NazwaProjektu>Application,
  • w pom.xml dopiszcie nazwę do <artifactId>wdtb-2026-backend</artifactId>,
  • w pom.xml ustawcie wersję z numerami indeksów osób z zespołu (R1.05): <version>1.0.0-<nrindeksu1>-<nrindeksu2>-<nrindeksu3></version>, np. 1.0.0-123456-123457-123458.

Hibernate tworzy tabele od nowa przy każdym starcie (ddl-auto=create-drop), a potem wczytuje data.sql. Dlatego dane dopisane ręcznie w konsoli H2 znikają po restarcie, a dane z data.sql zostają.

C4. Wysłanie zmian

W IntelliJ: Git → Commit, potem Push.

Prezentacja na początku LAB 02. Kolejne zajęcia zaczynamy od prezentacji wizytówek. Przed prezentacją:

  1. w IntelliJ Git → Pull, żeby mieć wersję wysłaną na LAB 01,
  2. uruchomcie aplikację (zielona strzałka obok main w klasie <NazwaProjektu>Application),
  3. otwórzcie http://localhost:8080: na stronie jest wypełniona wizytówka, bez [uzupełnij].

Na jej podstawie przedstawiacie autorów, pomysł (problem, klient, najważniejsze funkcje) i zmiany wprowadzone na LAB 01.
