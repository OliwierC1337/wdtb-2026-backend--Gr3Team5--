Roadmapa laboratoriów

Każde laboratorium dokłada jedną warstwę backendu, a reguły projektu rosną razem z kodem. Laboratoria 01–02 mają instrukcje. Pozostałe opisują zakres i wymagania; instrukcje pojawią się przed zajęciami. Wymagania laboratoriów: Wymagania. Zaliczenie i obecności: Zasady. Pracujemy na zajęciach; kryteria oceny prowadzący podaje zawsze na początku zajęć.

LAB 01 · Start (bez oceny)

→ instrukcja LAB 01

  • powitanie i omówienie przedmiotu: backend, baza danych, architektura warstwowa (strona główna)
  • zespół i repozytorium: wpis do arkusza zespołów (Excel, zakładka grupy), fork szablonu
  • praca zespołu: uruchomienie aplikacji w IntelliJ, pomysł na projekt, nazwa projektu w repozytorium i kodzie, konta w data.sql, wizytówka na stronie startowej
  • Reguły: R1.01–R1.05

LAB 02 · Encje i dane startowe

→ instrukcja LAB 02

  • na początek: prezentacja wizytówek z LAB 01: zespół uruchamia aplikację i pokazuje wypełnioną wizytówkę na http://localhost:8080 (autorzy, pomysł, zmiany)
  • wprowadzenie: encje na przykładzie kawiarni, typy kolumn, klasa wbudowana @Embeddable
  • encje JPA: @Entity, @Table, @Id, @GeneratedValue, @Column, @Enumerated(STRING)
  • zadanie: 3 własne tabele z pomysłu zespołu, bez relacji, dane startowe w data.sql, sprawdzenie w konsoli H2
  • typy: BigDecimal dla kwot, enumy jako tekst, daty
  • praca zespołowa na jednym laptopie, sekcje w data.sql
  • konsola H2: czytanie DDL wygenerowanego przez Hibernate, select na każdej tabeli, pokazanie przebiegu w GitHub Actions (tag lab-2 opcjonalnie)
  • Reguły: R2.01–R2.05 (ocena 4), R2.06–R2.07 (ocena 5: enum i @Embeddable)

LAB 03 · Repozytoria i zapytania

  • higiena encji: LAZY, STRING, konstruktor, @Embeddable
  • Spring Data JPA: zapytania pochodne, @Query (JPQL), GROUP BY, projekcje, Pageable
  • problem N+1: QueryCounter, @EntityGraph, JOIN FETCH
  • „pytania inwestora” i testy @DataJpaTest

LAB 04 · Serwisy i komponenty

  • kontener IoC: @Component, @Service, @Configuration + @Bean, wstrzykiwanie przez konstruktor, cykl życia i zasięg beana
  • warstwa application: przypadki użycia, @Transactional (propagacja, readOnly, rollback)
  • reguły biznesowe w kodzie i wyjątki domenowe
  • moduły: pakiet api jako publiczny kontrakt modułu; relacje encji między modułami zastępujemy identyfikatorami
  • testy jednostkowe z Mockito, testy parametryzowane

LAB 05 · Kontrolery REST

  • @RestController, mapowania HTTP, ResponseEntity, kody odpowiedzi, nagłówek Location
  • DTO jako rekordy, mapowanie encja ↔ DTO
  • Bean Validation (@Valid, @NotBlank, @Future), @RestControllerAdvice + ProblemDetail
  • stronicowanie i filtrowanie w API, endpointy raportowe z pytaniami inwestora
  • OpenAPI / Swagger UI (springdoc), pliki .http w IntelliJ
  • @WebMvcTest + MockMvc

LAB 06 · Rozbudowa

  • zdarzenia aplikacyjne: ApplicationEventPublisher, rekordy *Event, @TransactionalEventListener
  • konfiguracja: @ConfigurationProperties jako rekord, profile
  • @Scheduled: wygaszanie rezerwacji, przypomnienia, raport dnia
  • zadanie dodatkowe: integracja z API innego zespołu przez RestClient w infrastructure, z testem MockRestServiceServer

LAB 07 · Odrabianie

  • nadrobienie niezaliczonego materiału (nieobecności, oceny niedostateczne)
  • poprawa czerwonych laboratoriów zespołu
  • zespoły bez zaległości: krótka prezentacja projektu i zadania dodatkowe podnoszące ocenę
